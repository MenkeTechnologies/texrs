# Cases that do NOT match real tex yet, one per line, with the reason.
# BUGS.md explains each class. This file is a BASELINE, not an excuse: the gate
# fails on any case that diverges and is NOT listed here, and it also fails on a
# listed case that has started PASSING -- so the list cannot quietly go stale.
#
# Currently EMPTY: all 27 cases match tex 3.141592653 (TeX Live 2026).

undefined_cs.tex   An undefined control sequence is not an error. tex reports
#                  `! Undefined control sequence.' and expands it to nothing;
#                  texrs prints its NAME into the message stream and exits 0.
#                  Found by scripts/fuzz_parity.sh. Fixing it means an error
#                  path through the expander that the milestone does not have.
plain_count0.tex   The oracle is `tex' with the PLAIN format preloaded, where
#                  \count0 is the page number and already holds 1. texrs starts
#                  every register at zero, as INITEX does, and loads no format.
#                  Not an engine bug -- a startup-state difference, recorded so
#                  it cannot be mistaken for one later.
edef_freezes_conditional.tex
#                  `\edef' does not decide a conditional in its body at
#                  DEFINITION time. tex expands `\ifcase\count1 ZERO\else
#                  OTHER\fi' while reading the \edef -- \count1 is 0 there, so
#                  the body becomes the single token run `ZERO' and a later
#                  `\count1=5' cannot move it. texrs keeps the conditional in
#                  the body and decides it at use time, printing OTHER.
#                  Found by scripts/fuzz_parity.sh (seed 77).
ifx_after_edef_conditional.tex
#                  The same root cause seen through `\ifx': two \edef bodies
#                  that tex froze to the same token run compare equal there and
#                  unequal here, because texrs still has the unexpanded
#                  conditional in one of them. Fixing the entry above fixes
#                  this one; it is listed separately so the gate proves it.
param_brace_delim.tex
#                  `#{' -- a macro parameter delimited by the left brace, which
#                  tex then puts back (`\def\a#{[X]}' called as `\a{Y}' prints
#                  `[X]{Y}'). texrs refuses the definition instead. Before that
#                  it PANICKED: the argument reader indexed past the end of the
#                  parameter list on a trailing `#'. Found by `cargo fuzz run
#                  lower'; the crashing input is kept as
#                  fuzz/corpus/lower/crash_param_brace.tex.

group_restores_count.tex
#                  `\begingroup' scopes the macro table but not the count
#                  registers: a `\count0=2' inside one survives `\endgroup',
#                  where tex restores the outer value. The brace form does save
#                  them -- lower.rs wraps a `{...}' body in Cmd::Group with the
#                  registers it assigns -- so the two group forms disagree,
#                  which is the bug. Found by writing examples/globals.tex,
#                  which is why that example is not in examples/.
expandafter_brace_arg.tex
#                  `\expandafter\wrap\expandafter{\inner}' expands `\inner'
#                  but loses the brace group: texrs prints `[]{INNER}' where tex
#                  prints `[INNER]', so the held token is put back after the
#                  expansion rather than in front of the argument it was meant
#                  to take.
let_char_token.tex
#                  `\let\egroup=}' copies a CHARACTER token, and printing one
#                  through \message must print the character. texrs prints the
#                  name with the trailing space a multi-letter control word
#                  gets (tex.web 294's print_cs), so the stream ends
#                  `INSIDE\egroup ' where tex ends `INSIDE\egroup'. The
#                  meaning-copy half of \let is in parity; this is the
#                  char-token half.
def_in_conditional_arm.tex
#                  A `\def' inside an arm of a RUN-TIME conditional is executed
#                  while lowering, and lowering emits both arms because neither
#                  is decided yet -- so the else arm's definition overwrites the
#                  then arm's and the losing branch wins. tex interprets and
#                  runs only the arm it took: it prints `<a>' where texrs prints
#                  `[a]'. This is a miscompile rather than a refusal, which is
#                  what makes it worth a case: nothing errors, the answer is
#                  just wrong. It blocks LaTeX's `\newcommand{\x}[n]{...}',
#                  whose argument-count dispatch is exactly a chain of
#                  `\ifnum...\def...\else'. Fixing it needs the macro table to
#                  be run-time state, or the conditional to be decidable while
#                  lowering; neither is a small change.


cond_ifcase_negative.tex
#                  A NEGATIVE `\ifcase' selector takes case 0 instead of the
#                  `\else' branch. tex.web 509 skips n cases and takes the
#                  (n+1)th, so a selector below zero or past the last `\or'
#                  matches nothing and `\else' runs; do_ifcase counts down with
#                  `while remaining > 0', which a negative n never enters, so
#                  it falls straight through to case 0. tex prints DEFAULT
#                  where texrs prints ZERO. Like def_in_conditional_arm.tex
#                  this is a wrong answer rather than a refusal: nothing
#                  errors. Found by writing the reference manual's
#                  conditionals chapter.
